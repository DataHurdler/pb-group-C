# Module 04 — Capstone: Your Prompt Kit

Status: draft
Time: 14:20–15:30 (70 min — lecture 10 / activity 60)
Objective: LO4

## Objective

By the end of this module, participants will be able to **evaluate** output
against criteria written before testing, **refine** one change at a time, and
**package** the result as a reusable template with stated limits.

## Why this module is here

A good prompt used once saves an hour. A tested template used every week saves
a lot more. This module adds the two habits that turn prompting from guesswork
into a method: **decide what good looks like before you look**, and **change one
thing at a time**. It ends with a judgment call participants write down: what
they wouldn't use the template for. Share-outs happen in Module 05.

### Three things to say in the brief

1. **Criteria first.** If you decide what "good" means after reading the output,
   you'll accept anything that reads well. Write yes/no checks before the first
   run.
2. **One change at a time.** Changing three things at once can make the output
   better, but you won't know which change did it, so you can't reuse the lesson.
3. **A template is a prompt with slots and a label.** `[SLOTS]` for what
   changes each time; a header saying what it's for, what it's *not* for, and
   what to check. If someone else can't use it, it isn't a template yet.

## Key points

1. Write criteria before you run the prompt.
2. Change one thing, rerun, log it.
3. A template needs slots, a use / don't-use header, and its own checks.
4. Knowing what *not* to hand to AI is part of the skill: final decisions,
   anything you can't verify, anything you couldn't defend if challenged.

## Common problems and what to do

| Problem | Response |
| --- | --- |
| Criteria are vague ("good", "professional") | "How would you check that in five seconds?" Rewrite as yes/no |
| Changes several things per round | Ask "What did you change?" and wait. Then ask them to undo all but one |
| Picks a one-off task | "When will you do this again?" If never, choose another task |
| Partner can't fill in the slots | That's the test working. The slot names need to say what goes in them |
| Finishes early | Lab 04 early-finisher task: add a worked example |

## If running behind

1. Shrink the scope, not the time: drop to one refinement round in step 4
2. Shorten the partner test to "read it and tell me what's unclear" without
   running it (saves ~5 min)
3. Last resort: borrow up to 10 minutes from the Module 05 buffer
