# Module 04 — Capstone: Your AI Use Case

Status: draft
Time: 14:20–15:30 (70 min — lecture 10 / activity 60)
Objective: LO4

## Objective

By the end of this module, participants will be able to **design** an AI use
case for a recurring task: test a prompt against criteria written in advance,
refine one change at a time, and complete a one-page plan covering value, risk,
and data handling.

## Why this module is here

A good prompt used once saves an hour. A tested use case built into a weekly
task saves far more, but in a workplace it also has to survive a few questions:
*what does it actually save, what could go wrong, and are we allowed to?* This
module answers those on one page, the
[use-case canvas](../../handouts/use-case-canvas.md), and adds the two habits
that make prompting a method rather than guesswork: **criteria first** and
**one change at a time**. Pitches happen in Module 05.

### Four things to say in the brief

1. **Pick a task, then the step.** AI rarely takes over a whole task. Map the
   steps and choose where it saves the most time while you keep the
   judgment calls.
2. **Criteria first.** If you decide what "good" means after reading the
   output, you'll accept anything that reads well. Write yes/no checks before
   the first run.
3. **One change at a time.** Changing three things at once can make the output
   better, but you won't know which change did it.
4. **Count honestly.** Time saved is measured *after* checking the output. A
   use case that saves 20 minutes and needs 15 minutes of checking saves 5.

## Key points

1. Map the task. Give AI the steps it's good at; keep the judgment calls.
2. Write criteria before you run the prompt; change one thing per round.
3. A use case is a template **plus** the answers to: what does it save, what
   could go wrong, are we allowed to?
4. Start with a two-week pilot and measure it, not a permanent change.

## Common problems and what to do

| Problem | Response |
| --- | --- |
| Criteria are vague ("good", "professional") | "How would you check that in five seconds?" Rewrite as yes/no |
| Changes several things per round | Ask "What did you change?" and wait. Then ask them to undo all but one |
| Picks a one-off task | "When will you do this again?" If never, pick another |
| Doesn't know their employer's AI policy | Normal. "Find out" goes in the pilot plan as step one |
| Wildly optimistic time savings | "Does that include checking the output?" |
| Owner-founders say the policy box doesn't apply | It does, in another form: what are you comfortable putting in this tool, and what would your clients expect? |
